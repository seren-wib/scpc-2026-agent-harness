# SCPC 2026 AI Agent Harness

개인 기기 에이전트의 요청 맥락(task JSON)을 읽고 판단 결과(answer JSON)를 생성하는 **규칙 기반 하네스**. SCPC 2026 예선(DACON) 제출물이다.

- 최종 점수 **0.8408** (baseline 0.5206에서 +0.32, 상위 100 커트라인 0.8788)
- 로컬 dev 정확도 **0.9416** (focal 1.00 / control 1.00 / target 0.99 / policy 0.98 / plan 0.98 / scope 0.93)
- 외부 의존성 없음 — Python 3.12 표준 라이브러리만, 단일 파일 984행, 결정론적(연속 실행 md5 동일)

> **위 두 숫자는 서로 다른 커밋에서 나온다.** 최종 제출로 선택한 0.8408 답안은 커밋 `4e05822`
> (*fix(guard): withdraw the resolved-cell promotion*)가 재현하며, 그 시점의 dev는 0.9371이다.
> 현재 HEAD는 마감일의 마지막 실험 두 개를 더 담고 있어 dev가 0.9416까지 오르지만, 공개 점수는
> 0.8357로 내려갔다. dev에 표본이 없는 과제 가족에서 dev 기준 개선이 뒤집힌 사례이며,
> [한계](#한계)에서 다루는 현상 그 자체다.

## 무엇을 푸는가

에이전트가 사용자 요청을 받았을 때 다음을 판단해야 한다.

| 축 | 판단 내용 | 가중치 |
|---|---|---|
| `focal` | 요청이 가리키는 참조 대상이 무엇인가 | 0.18 |
| `control` | 그대로 진행할지, 수정할지, 되물을지, 멈출지 | 0.18 |
| `plan` | 어떤 행동 계획을 세울 것인가 | 0.18 |
| `content_scope` | 무엇을 어디까지 공개할 것인가 | 0.17 |
| `policy` | 어떤 위험 플래그를 세울 것인가 | 0.13 |
| `target` | 결과를 어디로 보낼 것인가 | 0.12 |
| `semantic_response` | 사용자에게 뭐라고 답할 것인가 | 0.04 |

축은 독립이 아니라 게이트로 묶여 있다. `focal`이 틀리면 해당 과제는 사실상 0점이고, `focal`이 맞아도 `target`이나 `control`이 틀리면 `scope`/`policy`/`plan`이 전부 0점이 된다. 따라서 상류 판단의 수리는 자기 가중치와 게이트 해제분을 이중으로 벌어들인다.

답안 생성에 외부 LLM API를 쓰는 것은 금지돼 있다. 제공된 고정 SLM 클라이언트와 자작 규칙 로직만 사용한다.

## 실행

**데이터는 저장소에 포함돼 있지 않다.** 대회 배포물이라 재배포하지 않는다. 대회에서 받은 파일을 다음 위치에 두고 실행한다.

```
docs/data/
├── dev_tasks.jsonl        연습 과제 120개
├── dev_answers.json       위 120개의 참조 정답
├── screening_tasks.jsonl  채점 대상 700개
└── sample_submission.csv  제출 CSV 형식 예시
```

```sh
python3 run.py dev        # dev 120개 실행 + 로컬 채점 리포트
python3 run.py screening  # screening 700개 실행 + submission.csv 생성/왕복 검증
```

로컬 채점기(`score_local.py`)는 공식 baseline 노트북 셀 11의 추출본이며 `semantic_response`를 항상 0으로 주는 보수적 근사다. 로컬 점수의 천장은 약 0.96이다.

## 설계 — 입력 해석 원리

하네스는 과제마다 다음 순서로 판단한다. 각 단계는 개별 문항이 아니라 **입력 구조의 해석 원리**로 작성돼 있다.

**1. focal 해석 사다리.** marker 간접 참조(`그 항목`, `앞서 고른 것`) → history 문장 내 코드 점수화 → 객체 상태 우선순위 순으로 참조 대상을 좁힌다. 지목 문법이 아니라 확정·승인 사건의 위치가 결정한다.

**2. 꼬리 절 파서.** 요청 문장 끝에 붙는 `단,` / `다만,` 구절이 `target`과 `control`을 동시에 결정하는 최상위 신호다. 절의 의도를 local(내부 처리)·stop(중단)·confirm(확인)·scope(축소)로 분류한다. 대상 과제의 61.7%가 이 경로를 지난다.

**3. 절 우선 원칙.** 절 신호와 record 신호가 충돌하면 절이 절대적으로 우선한다. 이를 뒤집으려는 시도가 서버 실측으로 세 번 기각됐다(각각 −0.010 / −0.017 / −0.035).

**4. 경계 격자.** 꼬리 절이 없는 record 경로는 2차원 격자로 판정한다. `share_boundary_update` 값이 기본 판정을 적고(`local_update`→proceed / `redacted_*`→amend / `dispatch_blocked`→ask / `user_binding_pending` 동반→hold), `ambiguous_target`이 한 단계 격상시키며 `ambiguous_focal`은 격상시키지 않는다. dev의 record 경로 21건에 전수 정합한다.

**5. 출력 조립.** 확정된 focal/target/control 위에서 scope·policy·plan·응답 문장을 조립한다.

상세 구조는 [docs/harness_architecture.md](docs/harness_architecture.md)에 함수·행 단위로 서술돼 있다.

## 한계

**입력만으로 결정되지 않는 성분이 존재한다.** dev 과제 `84342b`와 `1a4b36`은 record 8종·객체 구성·세션 골격이 완전히 동일한데 정답이 다르다(`summary` vs `redacted`). 열두 가지 판별 가설이 전부 실패했다. 입력이 같으면 답도 같아야 하므로, 이는 규칙이든 LLM이든 **입력만으로 도달 가능한 정확도의 상한이 1.0이 아님을 보이는 실물 증거**다. 남은 dev 누수는 대부분 이 성분이다.

**연습 데이터의 앵커는 연습 데이터 밖으로 전이되지 않는다.** dev에 완전히 일치하는 규칙(26/26 포함)도 dev에 표본이 없는 과제 가족에서는 음수를 냈다. dev는 record 값 조합의 좁은 표본이다. 값 어휘에 건 규칙은 미관측 분포에서 배신하며, 구조 관계에 건 규칙만 전이된다.

**`semantic_response` 축은 개선 여지가 확인되지 않았다.** 어휘 정렬 전면 재작성이 신구 동점(+0.0003)이었다.

## 접근 방식

정답이 공개된 연습 과제 120개와 하루 3회의 서버 점수 델타만으로 채점 생성기의 내부 구조를 역추론하고, 그 구조를 일반화 규칙으로 옮기는 방식을 썼다. 운용 규율은 다음과 같았다.

- 불확실한 가설은 한 번에 하나씩 검증하고, 검증된 개선만 묶어서 제출한다
- 모든 변경은 로컬 dev 점수 하한 이상을 유지한다
- 제출 전에 몇 건이 정확히 의도한 이유로 바뀌는지 diff를 세고 원인을 귀속시킨다
- 제출 전에 "델타가 X면 가설 Y가 참"이라는 해석 기준표를 미리 작성한다
- 음수·무변화로 끝난 실험은 전부 재시도 금지 목록에 기록한다

19회 제출 중 9회 채택, 10회 revert. 상승분의 8할이 세 번의 제출에서 나왔고 셋 다 표면 패턴이 아니라 생성기 구조의 발견이었다. 전체 기록은 [docs/캠페인_회고_7일.md](docs/캠페인_회고_7일.md)에 있다.

## 규정 준수

- 답안 생성은 고정 SLM 클라이언트와 자작 규칙 로직만 사용했다. 외부 LLM으로 생성한 답안은 없다
- 모든 규칙은 과제 가족(템플릿) 단위의 일반화 규칙이다. 특정 문항 맞춤 예외, task_id 하드코딩, 수작업 답안표는 없다
- 열람 산출물은 전부 스크립트 기반 집계이며 [analysis/](analysis/)에 보존돼 있다
- 대회 배포 데이터와 주최측 문서는 이 저장소에 포함하지 않는다
